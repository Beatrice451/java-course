# Введение в ООП

## Что такое ООП?

ООП (Объектно-ориентированное программирование), как ни странно, ориентировано на объекты. Срыв покровов, не правда ли?  
ООП - это подход к разработке программ, в котором программа представляется как совокупность взаимодействующих объектов. Начнём с примеров. Нам нужно хранить всякую информацию о студентах. Например имя, возраст и оценки. Самый тупой вариант:
```java
String student1Name = 'Ivan';
String student1Age = 99;
List<Integer> student1Grades = new ArrayList<>();
student1Grades.add(5);
student1Grades.add(4);

String student2Name = 'Aleg';
String student2Age = 12;
List<Integer> student2Grades = new ArrayList<>();
student2Grades.add(3);
student2Grades.add(3);

String student3Name = 'Arkadiy';
String student3Age = 1234;
List<Integer> student3Grades = new ArrayList<>();
student3Grades.add(1);
student3Grades.add(1);

// ...
```

Что тут плохо? Данные одного студента разбросаны по отдельным переменным, приходится следить, какие переменные относятся к кому. А если студентов 10? 100? 1000? В таком случае нужно использовать **класс**. 

```java
class Student {
	String name;
	int age;
	List<Integer> grades = new ArrayList<>();
}
```

В этом примере мы **не создали студента**. Мы описали, что такое студент. Какие данные будет храниться о каждом студенте.

**Класс позволяет нам описать собственный тип данных, состоящий из нескольких связанных данных.**

## Класс и объект
Важно запомнить:
- Класс - описание того, какими будут объекты: какие у них есть данные и методы;
- Объект - конкретный экземпляр класса.

Простыми словами: класс - это чертёж, а объект - то, что по чертежу было создано. Другая аналогия: у нас у всех есть некоторое представление о человеке - наличие двух рук, двух ног, головы, туловища и т.д. Есть некоторый шаблон - этот шаблон можно назвать классом. Реально же существующий человек (фактически экземпляр данного класса) является объектом этого класса.

Объект (экземпляр) объединяет:
- **состояние** - данные, которые он хранит;
- **поведение** - действия, которые он умеет выполнять.

### Создание объектов, оператор `new`

Собственно, а как создать конкретного студента? Создание объектов класса мало чем отличается от создания переменных. Указываем название класса (по сути тип данных) и потом название объекта.

```java
Student student;
```

Обратите внимание. Мы ещё **не создали сам объект!** Мы создали переменную `student`, которая может хранить ссылку на объект типа `Student` в памяти (объявление переменной). Но самого объекта в памяти ещё нет!

А теперь создадим сам объект с помощью оператора `new`. С ним мы сталкивались ранее и теперь разберём подробнее:

```java
student = new Student();
```

`new` используется для создания объекта в памяти.  Если прям простыми словами, то код:

```java
Student student = new Student();
```
буквально означает 
>Создай объект `Student` и сохрани ссылку на него в переменной `student`.

То есть `student` - объект (экземпляр) класса `Student`? Ну... 

Самое время вспомнить про ссылочный тип данных. Переменная ссылочного типа хранит ссылку на объект либо специальное значение `null`, означающее отсутствие ссылки на объект. Не сам объект и не его содержимое! Ссылку на объект в памяти!
То есть `student` - не объект класса! Это ссылка на объект, а сам объект - то, что находится в памяти и то, на что ссылается переменная `student`.

```java
Student a = new Student(); 
Student b = a;
```

Здесь объект **один**! И есть две ссылки на него - `a` и `b`. 

:::tip Так в итоге экземпляр или объект?
Никакой разницы. Экземпляр класса и объект класса - синонимы. И то, и то означает конкретную реализацию класса, созданную с помощью оператора `new`.
:::
## Поля
Переменные, объявленные на уровне класса называются полями. Они предназначены для хранения данных об объекте класса. Опять пример со студентами:

```java
class Student {
	String name; // поле
	int age; // поле
	List<Integer> grades = new ArrayList<>(); // не поверите. Поле
}
```

Теперь создадим объект класса и обратимся к его полю:

```java
void main() {
	Student std = new Student();
	std.name = "Ivan";
	IO.println(std.name);
}
```

Обращение к членам объекта (полям и методам) осуществляется с помощью точки. Так мы можем читать и записывать значения полей. 

:::warning ТОЧКА = ЗЛО
Забегая немного вперёд: почти никогда мы не обращаемся к полям объекта через точку. Просто примите к сведению.
:::

## Методы

Как мы уже выяснили, класс описывает информацию об объектах с помощью полей. А работает он с этой информацией посредством **методов**. С методами мы уже сталкивались. Например `main()`. Или методы из четвёртой практической работы первого блока. До изучения классов методы были просто отдельным именованным блоком кода:

```java
public static int add(int a, int b) {
	return a + b;
}
```

Теперь методы становятся частью класса и описывают **поведение объектов этого класса**.
Опять вернёмся к бедным студентам и создадим пару методов:

```java
class Student {
	String name;
	int age;
	List<Integer> grades = new ArrayList<>();
	
	void sayHello() {
		IO.println("Hello! My name is " + name);
	}
}
```

В примере выше мы создали простейший метод. Теперь вызовем его:

```java
void main() {
	Student std = new Student();
	std.name = "Aleg";
	
	std.sayHello(); // Hello! My name is Aleg
}
```

Обратите внимание на две вещи:
1. Теперь у методов необязательно писать `public` и `static`. Достаточно возвращаемого типа данных и названия. 
2. Метод принадлежит **экземпляру класса**. Мы пишем не `sayHello()`, не `Student.sayHello()`, а `std.sayHello()`.

Как обсуждалось выше, к методам мы обращаемся через точку. И вот тут вспомните про то, что я говорил ранее - скобки при вызове метода и почему это важно: 
```java
class Test {
	String text;
	
	void text() {
		//...
	}
}

void main() {
	Test t = new Test();
	t.text; // обращение без скобок - обращение к полю
	t.text(); // обращение со скобками - вызов метода
}
```

## `this`, ссылка на текущий объект

Для ссылки на текущий объект используется ключевое слово `this`. 
```java
class Student {
	String name;
	
	void sayHello() {
		IO.println(this.name); 
	}
}

// ...

void main() {
	Student s1 = new Student();
	Student s2 = new Student();
	
	s1.sayHello(); 
	s2.sayHello();
}
```

При `s1.sayHello();` `this` будет ссылаться на `s1`, при `s2.sayHello();` - на `s2`. А зачем вообще это надо? Ведь всё прекрасно работает и без `this`. Вопрос хороший. В простых случаях `this` в принципе не нужен:

```java
class Student {
	String name;
	
	void sayHello() {
		IO.println(name); // всё прекрасно работает
	}
}
```

Тут всё работает, потому что в этом методе имя `name` однозначно обозначает поле объекта, поэтому `this` можно опустить. А теперь другой пример:
```java
class Student {
	String name;
	
	void setName(String name) {
		// name = name    а что из этого ссылается на поле, а что на параметр?
		this.name = name;
	}
}
```

В примере выше `this.name` означает поле объекта, а `name` - параметр метода. 

## Статические методы
:::warning ЗАПОМНИТЕ, РАДИ БОГА
**СТАТИЧЕСКИЕ! НЕ СТАТИЧНЫЕ! УПАСИ БОЖЕ ХОТЬ ОДНА ЖИВАЯ ДУША ПЕРЕПУТАЕТ** 
:::

Собственно, вернёмся к модификатору `static`, который видим ещё с самой первой лекции. В примерах выше все методы и поля относились к **экземпляру класса**. Но иногда нужно, чтобы метод относился к **самому классу**. Для этого и используется модификатор `static`. Например:
```java
class MathUtils {
	static int sum(int a, int b) {
		return a + b;
	}
}
```

Для использования метода `sum` нам **не нужно** создавать экземпляр класса:

```java
void main() {
	int result = MathUtils.sum(5, 3); // 8
}
```

Мы обращаемся к нему по **имени класса**, без создания объекта класса.

### Нюансики

Первое: статический метод не может обратиться к полю объекта, если поле является нестатическим. 

```java
class Student {
	String name;
	
	static void printName() {
		IO.println(name); // non-static чётатам can't be referenced from чотатам. Ошибка короче
	}
}
```

Такое поведение может показаться нелогичным и неоправданным на первый взгляд. Но на самом деле, всё просто. Проблема в том, что `name` принадлежит **конкретному** объекту.

Например:
```java
Student s1 = new Student();
Student s2 = new Student();
Student.printName(); // а чьё имя-то вызывать? От s1 или s2?
```

Но можно сделать по-тупому, если прям сильно хочется:

```java
class Student {
	String name;
	
	static void printName(Student s) { // явно передаём студента в метод
		IO.println(s.name); 
	}
}
```
___

Второе: статический метод не обладает `this`, потому что `this` ссылается на текущий объект, а статические методы в принципе не подразумевают наличие объекта. Ссылаться не на что.

### `main()`

Небольшое отступление по поводу метода `main()`. 
```java
class Main { 
public static void main(String[] args) {
 // ... 
	 } 
 }
```

Почему `main()` статический? Потому что JVM должна иметь возможность вызвать его через класс `Main`, не создавая объект класса `Main`.
